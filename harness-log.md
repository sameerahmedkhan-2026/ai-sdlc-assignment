# Harness Log

## Implementation and validation approach

The harness validates the implemented TypeScript backend and React frontend
without changing real user data. Each run uses the repository scripts, builds
the backend before checks that import its compiled application, records the
actual command and exit code, and stops on the first failure.

## Checks

| Check | Purpose |
|---|---|
| Lint | Static JavaScript/TypeScript lint validation. |
| Type-check | Backend and frontend compiler validation. |
| Build | Produces the compiled backend used by executable harness checks and the frontend bundle. |
| Unit | Domain transition and query behavior. |
| Contract | HTTP status, payload, CRUD, query, and ID behavior. |
| Integration | JSON persistence and restart-related repository behavior. |
| UI | Frontend test environment validation. |
| Security | Keyword/static checks for unsafe execution, secrets, and excluded scope; not full SAST. |
| Dependency | `npm audit` with every reported vulnerability treated as a failure. |
| Performance | Actual API benchmark over 1,000 persisted tasks covering list, filter, sort, create, retrieve, update, and delete with warm-up and measured samples. |
| Acceptance | Real API lifecycle scenarios, invalid transitions, deletion, and restart persistence using temporary data. |
| Traceability | Parses all FR, NFR, and SC IDs from the approved specification and validates task mappings, task references, and automated test/check references. |

## Evidence limitations

- A separate initial-generation log and pre-correction implementation snapshot
  were not captured before implementation corrections. No retrospective
  snapshot is represented as initial-generation evidence.
- The UI check remains a Vitest environment test rather than a browser-driven
  end-to-end test because no browser test runner is configured.
- The security check is a narrow static keyword/pattern check, not full SAST.
- Performance measures actual local HTTP operations on the current machine; it
  does not claim production-network performance.
- Acceptance and traceability checks validate the implemented scenarios and
  documented mappings, not human judgment.
